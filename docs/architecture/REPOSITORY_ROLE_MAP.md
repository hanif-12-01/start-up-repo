# WattWise AI — Repository Role Map

This document establishes the official classification and governance boundaries for every directory in the WattWise AI repository.

## Allowed Roles

- `ACTIVE_PRODUCT`: The primary production application codebase.
- `REFERENCE_IMPLEMENTATION`: Read-only reference implementation preserved for business logic and parity validation.
- `PRODUCT_DOCUMENTATION`: Authoritative specifications, PRDs, architecture guides, runbooks, and QA reports.
- `ML_RESEARCH`: Machine learning benchmarks, offline datasets, experimental models, and parity proofs.
- `ML_RUNTIME_SUPPORT`: Supporting runtime scripts, model weights, and embedded artifacts.
- `INFRASTRUCTURE`: Deployment scripts, hosting definitions, and cloud configurations.
- `DEVELOPER_TOOLING`: Coding standards, agent configurations, accessibility kits, and design token libraries.
- `HISTORICAL_OR_ARCHIVED`: Archived artifacts, past implementation records, or obsolete staging builds.
- `UNKNOWN_REQUIRES_REVIEW`: Directories requiring Product Owner review or clarification.

## Boundaries & Principles

1. **Active vs Reference Application**:
   - `wattwise-vercel/` is the single active product application.
   - `wattwise-laravel/` is retained strictly as a reference implementation.
2. **ML Research vs Application Inference**:
   - Offline research resides in `ml/benchmark/` and `ml/onnx-feasibility/`.
   - Production inference resides strictly inside `wattwise-vercel/` via embedded client-side ONNX Runtime Web (`onnxruntime-web`) and deterministic fallback services.
3. **Documentation Hierarchy**:
   - The authoritative product source of truth is `docs/PRD/WattWise_PRD_Current_Validation_Stage.md`.
   - Architectural and operational source of truth is `docs/architecture/CURRENT_APPLICATION_ARCHITECTURE.md`.
